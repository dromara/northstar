# 强化学习训练

> 「扩展 · 程序化交易」系列之一。前置阅读：[策略开发](/dev/strategy)（策略接口与回调机制）、[回测与策略探索](/dev/backtest)（验证手段）。

普通策略的"交易规则"由人编写（金叉买、死叉卖）；**强化学习（RL）策略**的规则是一个**神经网络模型**——平台在大量历史行情里让模型反复试错（训练），学会自己的开平仓策略。本文介绍平台 RL 能力的原理与用法。

::: info 当前版本范围
v1 支持 **DQN** 算法、**事件驱动决策点**、**指数合约**采样、显式验证时段与人工确认上线；PPO、Tick 级推理、实盘持续学习列入后续版本。
:::

## 总体架构：采样与训练分离

平台把 RL 拆成两半，由"模型目录"解耦：

```
┌────────────────────── Java（平台内）──────────────────────┐
│  RLTrainingService（按轮驱动训练任务）                       │
│    ├─ 采样：TradingEnvironment（每合约一个）                  │
│    │    = 行情回放游标 × 模组沙箱 × 推理代理                  │
│    │    跑出的 (状态, 动作, 奖励) 经验写入 CSV 分片           │
│    ├─ 训练：python train_round.py（子进程，无状态单轮）       │
│    └─ 评估：验证时段回测 → 胜率/盈亏比/交易数 → 推送前端       │
└───────────────────────────┬───────────────────────────────┘
                            │ 模型目录（磁盘文件契约）
┌───────────────────────────┴───────────────────────────────┐
│  Python（PyTorch）：读经验分片与 checkpoint → 训练           │
│  → 写回 checkpoint.pt（训练态）与 model.pt（推理用）          │
└────────────────────────────────────────────────────────────┘
```

- **Java 负责**：推理（DJL 加载 `model.pt`）、采样、流程编排、生命周期与页面服务；
- **Python 负责**：纯训练——每轮是一次无状态子进程，崩溃不会拖垮平台；
- **每轮训练完成后**，Java 侧所有推理代理同步热切换新权重。

## 三个核心概念

### 模型（Model）：策略代码定义的"形状"

一个模型 = 一个 RL 策略声明的完整规格：

- **`modelName()`**：模型名，即网络结构的"身份证"。神经网络由 Python 端 `training/registry.py` 按模型名注册（Python 是网络结构的唯一权威定义处）；
- **`rlSpec()`**：状态特征清单（如收益率、仓位占比，顺序敏感）、动作枚举（如 `HOLD / BUY / SELL`）、预处理类型；
- **超参数字段**：由 Java 端的 Hyperparameter 类用 `@Setting` 定义，前端表单动态渲染——**新增超参不需要改前端**。

模型目录缺失也不要紧：首次创建训练任务时会用策略现场规格自动生成（`models/{模型名}/metadata.json`）。

### 版本（Version）：一次训练的快照

**一个训练任务 = 恰好产出一个新版本**（如 v1、v2、v3……）。版本目录里保存着"这个版本是怎么练出来的"全部证据：

```
models/{模型名}/versions/v{n}/
├── metadata.json    # 血缘：父版本、是否继承权重、超参取值、随机种子、
│                    #   训练区间、触发条件摘要、网络结构、达标指标(accepted_by)
├── checkpoint.pt    # 训练态全量（继续训练从这里接力）
├── model.pt         # TorchScript 推理产物（模组实盘加载它）
├── rounds/          # 每轮经验分片 CSV
└── buffer.npz 等    # 训练侧跨轮状态
```

创建任务时的两个关键参数决定版本间的关系：

| 参数 | 语义 |
|---|---|
| **基准版本（baseVersion）** | `0` = 从零训练；否则以某历史版本为起点 |
| **权重继承（inheritWeights）** | `true` = 复制父版本 checkpoint，从父权重继续练；`false` = 仅继承特征定义与数据配置，权重从零初始化 |

### specHash：防止"策略变了、权重没换"

状态特征、动作、预处理共同决定模型的输入输出形状，平台对其计算 **specHash** 并写入模型与版本 metadata。继承权重时若父版本 specHash 与策略当前规格不一致，**拒绝 fork** 并输出结构化差异（告诉你哪个特征变了）——避免策略代码演进后与旧权重"张冠李戴"。

## 策略侧：RLStrategy 接口

只有实现 `RLStrategy` 接口的策略可以被训练（`GET /rl/strategies` 只列出这类策略）。它在普通策略之外增加六个钩子：

| 方法 | 职责 |
|---|---|
| `modelName()` | 声明绑定的模型名（须与 Python `registry.py` 注册键一致） |
| `rlSpec()` | 状态特征清单 + 动作枚举 + 预处理类型 |
| `observe(ctx, 合约)` | 把当前市场状态编码成**状态向量**（如收益率、相对均线偏离、当前仓位） |
| `shouldObserve(ctx, 合约)` | **决策点触发条件**：何时需要重新观测（纯指标判断，必须廉价） |
| `onAction(action, ctx, 合约)` | 把模型动作翻译成普通下单调用（`buyOpen` / `sellClose`…） |
| `reward(ctx)` | **奖励函数**：区间收益减去交易成本，可自定义形状（如权益击穿重罚） |

两个设计要点：

- **训推一致**：`observe` / `shouldObserve` / `onAction` 三个钩子在训练环境与实盘模组中跑**同一份代码**，训练学到的行为与实盘行为完全一致；
- **不绕过任何安全边界**：RL 动作最终走的还是 `ctx.submitOrderReq(...)`，风控过滤器、模组状态机、资金校验全部照常生效。

决策不是每根 K 线一次，而是由 `shouldObserve()` 事件驱动（SMDP 框架）：动作持有期间整段波段不触发监测，出现"涨不动"或止损迹象才记录一次状态转移。配套三条兜底：**超时强触发**（防死行情饿死训练）、**数据耗尽强制平仓**（正常结束）、**权益击穿判 terminated**（真失败）。经验数据带 `dt`（间隔 bar 数），训练按 `γ^dt` 折扣，模型才能学到时间价值。

## 训练任务：三段式生命周期

入口：**交易自动化 → 强化学习训练**。创建任务后按三个阶段推进：

```
创建任务 →【加载数据】→【启动训练】→ 运行中（可暂停/继续/调参/停止）
 CREATED      LOADING→READY    RUNNING → FINISHED / FAILED（可重试断点续训）
```

1. **创建任务**：选择策略（仅 RL 策略）→ 模型自动绑定 → 选基准版本与权重继承 → 多选合约（指数合约）→ 填三段日期与训练预算 → 超参数表单动态渲染（预填自基准版本）；
2. **加载数据**：把各合约的全时段历史数据一次性拉取落地为本地 CSV（任务级数据，随任务删除；只加载一次，重启后仍有效）；
3. **启动训练**：每轮 = 各合约环境串行采样（随机时间切片跑若干局）→ 经验汇入共享经验集 → Python 训练一轮 → 刷新全部推理代理权重 → 验证时段贪心评估（每 5 轮及最后一轮）→ SSE 实时推送指标到详情页。

任务字段里四个沙箱参数直接影响训练动态，都是创建时按任务持久化的：**沙箱初始资金**、**决策点超时强触发 bar 数**、**权益击穿阈值**、**单局最长 bar 数**。

**动态调参**：训练运行中可修改超参数（学习率、gamma、epsilon 等），**下一轮生效**——每轮开始前重读任务最新配置。

## 达标标准与"上线"

训练完结时，平台在**验证时段**（与训练时段隔离，防过拟合）做最后一次贪心评估，三条**同时满足**才把指标写入版本的 `accepted_by`：

- 胜率 > 50%
- 平均盈亏比 > 2
- 交易笔数 ≥ 100（统计显著性约束）

"上线"是人工动作：创建实盘/模拟盘模组，绑定该 RL 策略，并在策略参数里填 **推理模型版本目录**（如 `models/dqn-demo/versions/v1`）。模组加载时校验 specHash，不一致会快速失败——保证绑定的模型与策略代码严丝合缝。

## 常见问题

**新增一个 RL 模型要改哪些地方？**
① Python 端 `training/registry.py` 按新模型名注册网络结构；② Java 端新建 `RLStrategy` 实现并声明同名 `modelName()`。无需手工准备 metadata.json，首次创建训练任务时自动生成模型目录。

**Python 训练环境怎么准备？**
仓库根目录的 `env.sh`（Linux）/ `env.ps1`（Windows）会自动创建 RL 训练虚拟环境（安装 torch/numpy/gymnasium 等依赖）并写入 `NS_RL_PYTHON` 环境变量；也可用 `northstar.rl.python` 配置项直接指定解释器路径。

**训练失败怎么办？**
任务进入 FAILED 并记录原因；修复后（FAILED 状态允许调参）点 **重试**：平台丢弃失败轮的经验分片，从当前轮断点续训，采样序列由种子决定、可复现。

**想从头重新训练、版本号归零？**
版本号只增不减是刻意设计。想重来，手工删除整个模型目录 `models/{模型名}/`，下次创建任务会自动重新引导生成。

**详细设计哪里看？**
`northstar-rl` 模块的 `README.md`（模块结构与模型目录契约）与 `DESIGN.md`（完整设计：采样架构、决策点机制、版本血缘、前端交互、REST 契约），与源码保持一致。
